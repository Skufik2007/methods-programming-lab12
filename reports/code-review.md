# Code review кода, сгенерированного ИИ

Код приложения получен от отдельного экземпляра модели по промптам из
[`prompts/task1-webapp`](../prompts/task1-webapp). Сначала каждый ответ коммитится
без правок (коммиты с пометкой «без правок»), затем идут ревью, запуск, тесты и
исправления отдельными коммитами. Ниже перечислены реальные проблемы, найденные
при проверке. Формат каждой записи: что сгенерировал ИИ → в чём проблема → как исправил.

## 1. Зависимость от базы часовых поясов не объявлена

**Что сгенерировал ИИ.** В `app/config.py` валидатор `CLINIC_TIMEZONE` вызывает
`ZoneInfo("Europe/Moscow")`. Список зависимостей модель не дала: про пакет `tzdata`
сказано одной фразой в «Допущениях» в конце ответа.

**В чём проблема.** На Windows у `zoneinfo` нет системной базы IANA. Первый запуск
дымовой проверки упал ещё при импорте `app.db`:

```text
pydantic_core.ValidationError: 1 validation error for Settings
clinic_timezone
  Value error, unknown IANA time zone: 'Europe/Moscow'
```

Текст ошибки уводит в сторону: кажется, что неверно задана настройка, хотя на самом
деле не установлена зависимость. Та же ошибка возникнет в любом окружении без
системной базы часовых поясов, например в минимальном контейнере.

**Как исправил.** Добавил `tzdata` в обязательные зависимости `pyproject.toml` с
комментарием о причине. Предупреждение в «Допущениях» легко пропустить, а
зависимость в манифесте сработает всегда.

## 2. Дата у границы диапазона роняет сервер (500)

**Что сгенерировал ИИ.** В `app/schemas.py` (P1) тип `UTCDatetime` переводит любое
aware-значение в UTC через `value.astimezone(timezone.utc)`.

**В чём проблема.** Для значений у границ `datetime`, например
`0001-01-01T00:00:00+05:00`, перевод в UTC выходит за год 1 и бросает
`OverflowError`. Это не `ValueError`, поэтому Pydantic его не перехватывает:
исключение проходит через FastAPI, и на корректно оформленный, но бессмысленный ввод
клиент получает `500 Internal Server Error`. Ошибку нашла дымовая проверка P2. Модель
в P2 сама указала на это место в списке «что проверить на ревью», но исправлять не
стала, потому что промпт запрещал менять файлы P1.

**Как исправил.** `_to_utc` превращает `OverflowError` в `ValueError`, и клиент
получает обычный ответ 422 с понятным сообщением. Регрессионный тест:
`tests/test_review_regressions.py::test_02_extreme_datetime_is_422_not_500`. До
исправления он падал, после проходит.
